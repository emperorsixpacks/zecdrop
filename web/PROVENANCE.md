Hand-written, authored with Claude Code (model claude-sonnet-5-5): all app code and tests in src/, tests/ and e2e/ (routes, receipt page, operator pages and API client, wizard, warnings, lib/*, api/*), src/index.css (design tokens and Tailwind theme), eslint.config.js (create-vite 9.2.1 ships oxlint, not ESLint), vite.config.ts, playwright.config.ts (with e2e/operator/global-setup.ts, which starts the real operator binary) and the favicon; also hand-written: scripts/sync-operator-fixtures.mjs (lists the fixture files for the tests), scripts/check-explorer-links.mjs, scripts/hosted-config.mjs, scripts/serve-hosted.mjs and scripts/check-hosted.mjs (the hosting config and its checks) and, outside web/, ../scripts/capture-operator-fixtures.mjs, which drives the real operator binary and writes ../fixtures/contract/operator/ (those fixtures are program output, not authored by hand).
Generated by shadcn CLI 4.21.4 (`init -t vite -b radix -p nova`, then `add button badge card alert input label`, then `add progress table skeleton`, then `add textarea`): src/components/ui/*, src/lib/utils.ts and components.json; the CLI is not a dependency of this project (run it with `npx shadcn@4.21.4 add <name>`; components.json is what it reads), and the stylesheet it generated (`shadcn/tailwind.css`, custom variants no component here uses) is not imported; hand-edited afterwards (Badge shielded/done variants, Alert info/warning variants and role, link colour, and progress.tsx, which now passes `value` to Radix so the progressbar exposes aria-valuenow); for the 2026-10 redesign (DESIGN.md) button, badge, card, alert, input, textarea, label and progress were restyled by hand (new tokens, 44px targets, ruled card, ink and highlighter focus), and ui/popover.tsx was written by hand on the Radix Popover primitive in the same style (it did not come from the CLI).
Started from the create-vite 9.2.1 react-ts template: tsconfig.json, tsconfig.app.json, tsconfig.node.json, index.html and src/vite-env.d.ts, with strictness flags, the `@/` alias, the tests and e2e folders and our env typings added.
Libraries come from npm (see package.json and package-lock.json), including @playwright/test and @axe-core/playwright for the browser checks; the contract tests only read ../fixtures/contract/public-receipt*.json and the user-facing strings in ../crates/drop-core/src, which the Rust side owns.
No file was copied from another repository; the generated primitives come from the shadcn registry and the Vite template.
Fonts (bundled, served from our own origin; no request to a font host, so the Content-Security-Policy stays `'self'`): @fontsource-variable/archivo 5.3.0 (Archivo, variable weight and width, licence OFL-1.1; replaced Schibsted Grotesk in the 2026-10-15 redesign) and @fontsource/ibm-plex-mono 5.3.0 (IBM Plex Mono, latin 400 and 500, licence OFL-1.1), both from npm and imported in src/main.tsx; the fonts are not modified. The OFL requires the licence text to travel with the font files: each package's LICENSE ships in node_modules/@fontsource*/ and is not copied into dist.
The pictures in public/tour/ (the home page tour) are screenshots of this app, not drawings: e2e/operator/tour-shots.spec.ts drives the real operator binary on the mock chain with the public demo payout list, and opens the bundled real testnet receipt, in Chromium through Playwright; `cwebp` (libwebp, lossless) writes the files. Nothing in them was edited by hand.
The icons (sun, moon, check mark, plus, chevron) are small inline SVG paths drawn by hand for this project; no icon library or icon font is used.
The paper's grain, public/grain.png (a 128px tile of black speckle, 4KB), is written by scripts/make-grain.mjs, a hand-written script that uses nothing but Node's own zlib and a seeded random generator, so that the file is the same every time it is made; it is not a picture from anywhere. The screen's frame, its curves and the slips of paper are CSS in src/index.css; web/DESIGN.md ("The screen") says what each is for.
The QR codes (a campaign's funding request, a payslip as a link) are drawn by src/components/QrCode.tsx as one inline SVG path from the module matrix that uqr 0.1.3 (MIT, no dependencies, from npm) computes, loaded with a dynamic import only when a code is drawn; the tests read them back with jsQR 1.4.0 (Apache-2.0, a dev dependency that is not shipped), which did not draw them.
The practice mode's simulation (src/practice/) is hand-written for this project: its CSV importer, planner, fee and warnings are written afresh from the Rust sources of this repository (crates/drop-core, crates/drop-operator) that they reproduce, and its tests compare it with the operator's own captured answers (fixtures/contract/operator); it uses no library beyond the ones above.
The palette (Redacted paper, light and dark) is colour values chosen for this project and checked by src/colours.test.ts; the palette picker, the segmented control with its sliding thumb, the animated accordion, the confirm sheet (the browser's own <dialog>), the toasts, the count-up, the confetti and the glow are hand-written (CSS and a little TypeScript) on Radix primitives (Popover, Collapsible, ToggleGroup); the design lab the owner clicked through (a throwaway prototype outside this repository) was a reference for the motion and the palettes, and none of its code is used.
